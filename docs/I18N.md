# i18n status: IN-SCOPE — catalogued (react-intl) · G1/G2/G3/G5/G6/G9/G10/G12 live · ES owed (R3)

`davis-bike-hazard-map` is a public civic map/list UI and is **in scope** for
internationalization per `INTERNATIONALIZATION-STANDARD.md` §1 (row
`davis-bike-hazard-map` — "Public civic map") and §11 ("pseudolocale + RTL gates
on the map UI; first gates to land: G9, G10").

A prior change (PR #39) landed the static half of **G10** (logical-CSS) and
recorded **G9** as blocked-on-catalog. **This change builds the Phase-1 message
catalog and unblocks the catalog-dependent gates.**

## Framework (INTERNATIONALIZATION-STANDARD §2/§3)

**react-intl / FormatJS** (`react-intl` ^7, `@formatjs/intl` ^3, `@formatjs/cli`
for extraction) — the standard's canonical stack for **new** TS/React work and
the MF2 migration path. `formatMessage` / `<FormattedMessage>` / `defineMessages`
with **stable, explicit ids**; no ICU MF1-only patterns (§9). An `<IntlProvider>`
(`src/i18n/IntlProviderShell.tsx`) mounts at the app root with browser-based
locale `negotiate()` (`src/i18n/config.ts`), an `en` default, and a
`useLocale()` lang-switcher hook for a future selector.

## Catalog

- **Source of truth for languages:** `src/i18n/config.ts` (`SUPPORTED_LANGUAGES`
  = `en`, `es`). Add a locale here + a JSON file to ship it.
- **`src/i18n/locales/en.json`** — reference catalog, generated by
  `formatjs extract --format simple` (`npm run i18n:extract`). Its current message
  count is generated into [`DOCUMENTATION-AUDIT.md`](./DOCUMENTATION-AUDIT.md)
  rather than typed here, because a typed one goes stale silently: this line said
  **188** while the catalog held 214. Flat
  `{ id: message }`, directly consumable by `IntlProvider`.
- **`src/i18n/locales/es.json`** — **structure-only**: every English id present
  with an **empty** value (`npm run i18n:extract` runs `scripts/i18n/sync-es-skeleton.mjs`).
  **No machine translation** — davis had no prior Spanish, and §5 R3 forbids
  unreviewed MT in civic prod. At runtime the loader drops empty values so react-intl
  falls back to the inline English `defaultMessage` (gettext-style). Users see
  correct English until Spanish is authored; nothing renders blank.
- **Catalogued ≠ activated (issue #112).** Having a JSON file makes a locale
  *catalogued* — it's real for extraction, G3/G5/G6/G9/G12, and the pseudolocale
  pipeline — but `negotiate()` (`src/i18n/config.ts`) only ever selects a locale
  from the separate `ACTIVATED_LANGUAGES` list, today just `['en']`. Before this
  distinction existed, `negotiate()` matched any catalogued locale, so an
  `es`-preferring browser got `document.documentElement.lang = 'es'` while every
  string on the page still rendered in English via the `defaultMessage` fallback
  — a real, testable mismatch (`tests/unit/i18nConfig.test.ts`), not just an
  internal documentation gap. Promoting `es` means adding it to
  `ACTIVATED_LANGUAGES` **and** flipping `ES_REQUIRE_COMPLETE` in the same
  change, once R3 is actually done — not before.
- **Enum labels** (hazard category / severity / lifecycle / 311 hand-off stage /
  device-queue state) live in `src/i18n/labels.ts` via `defineMessages`, so the
  framework-free `shared/types.ts` (also imported by the server) stays clean.

### Spanish is owed — REVIEW-GATE R3

Spanish translation is tracked under **R3** (translation review workflow): every
string must pass `initial → translated → reviewed → final` before it ships; no
unreviewed MT. Until then **es is structure-only** and **G5 is scoped to
structural parity for es** (not hard completeness). Two-part promotion, done
together once translation actually lands: flip `ES_REQUIRE_COMPLETE = true` in
`scripts/i18n/check-parity.mjs` (makes es completeness merge-blocking) **and**
add `'es'` to `ACTIVATED_LANGUAGES` in `src/i18n/config.ts` (lets `negotiate()`
actually select it for a visitor — see "Catalogued ≠ activated" above). Doing
only the first half would leave the catalog complete but never negotiated;
doing only the second would reopen issue #112.

### G2 — why two passes, and what pass B does not cover

`no-literal-string-in-jsx` flags only literals appearing **directly in JSX**, so
a string produced in a `.ts` module and interpolated as `{step.label}` was
invisible to it twice over: wrong file, wrong node type. `check-extract.mjs`
*does* glob `src/**/*.{ts,tsx}`, but `formatjs extract` harvests only
`defineMessages` / `formatMessage` / `FormattedMessage` nodes, so a bare literal
was invisible to that half as well. Both halves were blind, for different
reasons — and the whole reporter feedback trail (`src/lib/reportTrail.ts`,
landed *after* the ratchet) passed the gate with 14 untranslated strings on it
(issue #164).

Pass B walks the TypeScript AST of every `.ts` file under `src/` and flags a
string or template literal that looks like display text — multi-word, or
capitalised and not an identifier/constant — unless it sits inside a
`defineMessages`/`formatMessage` call, is a property key, an import source, a
literal type, or a `'X' in window` feature probe. Two escape hatches, both of
which leave a written reason in the tree: an `i18n-exempt: <reason>` comment on
the literal's line, or a whole-file entry in the script's `DEFERRED` map — which
is the ledger below, and is printed on every green run rather than hidden.

#### Coverage is part of the verdict

Pass B used to walk `src/lib/**` only, and pass A only `src/App.tsx` plus the
top-level `.tsx` files in `src/components/`. Measured against the tree: the gate
**judged 35 of the 48 `.ts`/`.tsx` files under `src/`** and printed a clean
scan. `src/hooks/`, `src/i18n/`, `src/config.ts`, `src/main.tsx` and
`src/components/*.ts` were in neither pass, and nothing in the gate's own output
said so — this document was the only record, and it named a narrower set than
the code actually skipped. `src/hooks/useHazards.ts` was carrying an
untranslated rider-facing string through that hole (issue #200).

The gate now takes its universe from a filesystem walk of `src/` and **fails**
unless every file in it is judged by pass A, judged by pass B, or named in
`DEFERRED` with a written reason. It prints `judged N of M`. Three further
floors: an empty universe, an empty pass A or an empty pass B is a failure, not
a clean run; and `DEFERRED` is self-limiting — an entry naming a file outside
the universe, carrying a blank reason, or producing **no finding** when scanned
fails the gate until it is deleted. That last check fired on its first run:
`src/lib/landmarks.ts` had been deferred for "Davis place names — proper nouns",
and PR #191 had since moved that list into `place/davis.json`, so the entry had
been exempting an empty file while reading as a live exception. It is now
scanned, and clean.

`shared/**` and `server/**` are **outside the gate's universe** and are not
claimed to be clean. Running pass B's detector over them reports 344 candidates
— mostly SQL, diagnostics and OpenAPI metadata, which is why they are not in
scope — but `server/lib/routing.ts` (12 turn-by-turn step labels) and
`server/lib/pushNotify.ts` (the notification body) are rider-facing prose no
gate here can see. That is issue #201, and it is a decision about where
server-composed text is resolved, not a coverage bug.
`shared/types.ts`'s `HANDOFF_STAGE_LABELS` / `LIFECYCLE_LABELS` are the shape to
watch there; both already have catalogued twins in `src/i18n/labels.ts`, and
`reportTrail.ts` now routes through those rather than the raw enums.

### G9 — pseudolocale overflow (now live)

`scripts/i18n/gen-pseudo.mjs` transforms `en.json` → a git-ignored
`tests/i18n/en-XA.generated.json` (accents + ~40% expansion + `⟦ … ⟧`), protecting
ICU `{…}` argument/plural/select syntax **and** react-intl `<tag>` rich-text markup
so the pseudo message stays valid ICU. The catalog is injected into the running
provider via `window.__i18nTest`, exposed **only** when the build sets
`VITE_I18N_TEST_HOOKS=1` (the `playwright.i18n.config.ts` build does; the
production deploy build does **not** — verified: `__i18nTest` is dead-code-
eliminated from `dist/`). `tests/i18n/pseudo-overflow.spec.ts` asserts
`scrollWidth ≤ clientWidth` on the **UI chrome** (header, tabs, filters, list,
panels, forms, controls) across all seven views on **desktop + Pixel-7 mobile**.
The Leaflet map surface (`.map-canvas` / `.location-picker-map` / `.leaflet-container`)
is **excluded** — its tiles/controls pan and scroll by design. It runs in the CI
`e2e` job (chromium), **not** the nightly `e2e-webkit` job.

### G10 — logical-CSS (static live; ar/he RTL mirror deferred)

then a catalog + QA task, not a CSS refactor.

## Deferred / out of scope for this change (honest ledger)

- **`src/lib/format.ts`** relative-time / distance / duration helpers
  (`timeAgo`, `formatDistance`, `formatDuration`) remain English-only, locale-free,
  and unit-tested. They produce user-facing phrases and are a **scoped follow-on**:
  migrating them to `Intl.RelativeTimeFormat` / `Intl.NumberFormat` (§2) is a
  separate change with its own acceptance tests, not silently skipped. The
  surrounding UI words that embed them ("Reported", "filed", "Updated", "Location:")
  **are** wrapped, with the helper output passed as an ICU placeholder.
- **G2 pass B, deferred files.** ONE module is outside pass B's scan, named with
  its reason in `DEFERRED` in `scripts/i18n/check-no-hardcoded.mjs`, printed on
  every green run, and deleted automatically-or-else by the self-limiting check
  above:
  - `src/lib/format.ts` — the relative-time/distance follow-on immediately above.

  **Closed (issue #200):** `src/lib/api.ts` and `src/hooks/useHazards.ts` were
  deferred here for the feed-load error, which reached a rider's `role="alert"`
  verbatim in **both** of its branches — the server's own English sentence
  (`body.message`, from a server with no catalog) in the common one, and the
  literal `Could not load hazards.` in the hook's fallback. The earlier reason
  on `api.ts` said its diagnostics were "developer-facing … none of which is
  rendered to a rider as prose", and the call chain contradicted it.

  The transport now throws an `ApiFailure` code — `offline`, `request`,
  `server`, `parse` — and `ListView` and `MapView` resolve it through
  `feedErrorLabel()` in `src/i18n/labels.ts` at the point of display, the same
  shape #173 used. The server sentence is kept on the error for diagnostics and
  is never rendered; a rejected `fetch` keeps the browser's own `TypeError` as
  `cause`, which is vendor English in no catalog. Both files are scanned.
  `api.ts` keeps per-literal `i18n-exempt` reasons on its URL and query
  templates, its `Bearer ` auth-scheme tokens, and its transport diagnostics
  (including the moderator-only photo fetch, which is behind a login and never
  on a rider's screen) — each stated on its own line, rather than one blanket
  file entry covering them and anything added to the file later.

  `tests/unit/feedErrorMessages.test.tsx` formats the whole path under a
  SENTINEL catalog, so a string that never reached the catalog fails: an English
  regex cannot tell correct output from defective output when both are English.

  **Closed (PR #191):** `src/lib/landmarks.ts` was deferred here for "Davis place
  names — proper nouns". #191 moved that list into `place/davis.json`, and the
  entry then exempted a file with nothing in it. The self-limiting check found
  it; the file is scanned and clean.

  **Closed (issue #173):** `geolocation.ts`, `photo.ts` and `push.ts` were also
  deferred here, for thrown `Error` text that DID reach the UI through the
  catalogued `{reason}` slot in `route.error.location`. They now throw a
  failure **code** instead of a sentence, resolved through
  `geolocationErrorLabel` / `pushErrorLabel` / `photoErrorLabel` in
  `src/i18n/labels.ts` at the point of display, and all three are back inside
  pass B's scan. The browser's own `GeolocationPositionError.message` is
  dropped for display and preserved as `cause`: it is vendor English, varies by
  engine, and is in no catalog.
